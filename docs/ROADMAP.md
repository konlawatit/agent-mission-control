# Roadmap: ฟีเจอร์ที่ควรมีต่อ

รวมไอเดียที่ควรทำต่อ เรียงตามความคุ้มค่า แต่ละข้อบอกว่ามาจากอะไรที่เห็นตอนใช้งานจริง จะได้ตัดสินใจได้ว่าทำอะไรก่อน

บันทึกเมื่อ 2026-11-26 หลังงานรอบ redesign, ห้องแยกตาม session, ไฟล์แนบ และอ่านข้อความย้อนหลัง

## 1. แจ้งเตือนเมื่อห้องรอคุณหรือทำเสร็จ (แนะนำทำก่อน)

**ทำไม:** ใช้หลายห้องพร้อมกันและปล่อยรันยาว ตอนนี้ต้องเปิด dashboard ดูเองว่าห้องไหนถามอะไรอยู่ ห้องที่ติด prompt ขออนุญาตหรือ AskUserQuestion จึงค้างอยู่นานโดยไม่มีใครเห็น

**แนวทาง:**
- ใช้ Notification API ของเบราว์เซอร์ ซึ่งบน Windows จะขึ้นเป็นแจ้งเตือนของระบบ
- เตือนเมื่อห้องเปลี่ยนเป็น `needs_input` หรือ `done` ตอนที่แท็บ dashboard ไม่ได้อยู่ข้างหน้า
- กดที่แจ้งเตือนแล้วเปิดห้องนั้นทันที
- เปิด/ปิดได้ใน sidebar ขอสิทธิ์แจ้งเตือนครั้งแรกตอนผู้ใช้กดเปิดเท่านั้น
- ระวังไม่ให้เตือนซ้ำรัวๆ: เตือน 1 ครั้งต่อการเปลี่ยนสถานะ และไม่เตือนห้องที่กำลังเปิดดูอยู่

**ขนาดงาน:** เล็ก ทำฝั่งหน้าเว็บอย่างเดียว ข้อมูลสถานะมีครบแล้วผ่าน SSE

## 2. ค้นหาย้อนหลังข้ามทุก session

**ทำไม:** เคยสั่ง Claude ในห้อง client-portal-api ว่า "หา session ที่ทำเกี่ยวกับ webhook กับ Venio" ซึ่งเสียโควตาให้ Claude ค้นแทน ทั้งที่ dashboard อ่าน transcript ได้อยู่แล้ว

**แนวทาง:**
- ช่องค้นหาที่ค้นใน transcript ทุกไฟล์ใต้ `~/.claude/projects` ผลลัพธ์เป็นรายการ session พร้อมโปรเจกต์ วันที่ และข้อความรอบคำที่เจอ
- กดผลลัพธ์แล้วเปิดอ่านตรงจุดนั้น ใช้ `readConversationPage` ที่มีอยู่ หรือสั่ง `claude --resume <id>` ต่อ
- ควรมี index ไว้เบื้องหลัง เพราะ transcript ใหญ่ได้หลายสิบ MB ต่อไฟล์ (ไฟล์ของห้องนี้ 66 MB)
- ข้ามบันทึกภายในก้อนใหญ่อย่าง `api-request-blob` แบบที่ตัว parser ทำอยู่
- ปลอดภัย: อ่านเฉพาะ `.jsonl` ใต้ `~/.claude/projects` เหมือน API อ่านข้อความย้อนหลัง

**ขนาดงาน:** กลาง ส่วนที่ยากคือ index ให้เร็วโดยไม่กิน CPU ตอนเซิร์ฟเวอร์ทำงาน

## 3. หน้าดูงานอัตโนมัติ (e2e-forge และ `claude -p` อื่นๆ)

**ทำไม:** session อัตโนมัติ (`entrypoint: sdk-*`) ถูกซ่อนจากรายการห้องแล้ว แต่ยังอยากรู้ว่างานพวกนี้เป็นอย่างไร เช่น คำถาม "เปิดไว้ทั้งคืนทำไมได้น้อยจัง" ของ e2e-forge

**แนวทาง:**
- เก็บ event ของ session อัตโนมัติไว้แยก ไม่ใช่เป็นห้อง แล้วสรุปตามโฟลเดอร์หรือ worktree เช่น `.worktrees/partner`
- แสดงจำนวนรันต่อชั่วโมง token ที่ใช้ รันที่พัง และช่วงที่ไม่มีงานเลย
- ข้อมูลส่วนใหญ่อยู่ใน transcript แล้ว (`entrypoint`, `turn_duration`, usage) ไม่ต้องให้ e2e-forge ส่งอะไรเพิ่ม

**ขนาดงาน:** กลาง

## 4. สรุปการใช้โควตาตามห้องและตามวัน

**ทำไม:** มีตัวเลข token ต่อห้องและมิเตอร์ 5 ชั่วโมงอยู่แล้ว แต่ยังไม่เห็นว่าห้องไหนหรืองานไหนกินโควตามากที่สุด จึงตัดสินใจยากว่าควรพักอะไร

**แนวทาง:**
- กราฟเล็กใน panel Usage: token ต่อชั่วโมงในรอบ 5 ชั่วโมง แยกตามห้องและงานอัตโนมัติ
- ใช้ `readUsageIncremental` ที่นับ usage จาก transcript อยู่แล้ว

**ขนาดงาน:** เล็กถึงกลาง

## ที่ไม่แนะนำตอนนี้

- **เปิดให้เข้าจากมือถือหรือเครื่องอื่น:** เซิร์ฟเวอร์ตั้งใจฟังแค่ `127.0.0.1` ถ้าเปิดออกนอกเครื่องต้องออกแบบเรื่องสิทธิ์เข้าใช้ใหม่ทั้งหมด ทั้ง token, TLS และการส่งคำสั่งเข้า terminal ความเสี่ยงสูงเกินประโยชน์ตอนนี้
- **ปุ่มอนุญาตทุกคำขออัตโนมัติ:** จะไปข้ามขั้นขออนุญาตของ Claude Code ที่มีไว้เพื่อความปลอดภัย ถ้าต้องการลดการถาม ให้ตั้ง permission rules ใน Claude Code เองดีกว่า

## เรื่องที่รู้แต่ยังไม่ได้แก้

- **ภาพตัวอย่าง (preview) ในคำถามที่มีภาษาไทยจะเหลื่อมนิดหน่อย** ยังไม่มีฟอนต์ความกว้างเท่ากันที่รองรับไทยใน `public/fonts`
- **ทดสอบแค่บน Chromium** ยังไม่ได้ลอง Safari และ Firefox
- **ไฟล์แนบเก็บนอกโฟลเดอร์โปรเจกต์** (`~/.agent-mission-control/attachments`) ครั้งแรกที่ Claude เปิดไฟล์อาจถามสิทธิ์อ่าน
- **ห้องที่ยังไม่มี hook ส่งชื่อ transcript มา** จะเดาจาก transcript ใหม่ล่าสุดในโฟลเดอร์ที่ยังไม่มีห้องไหนใช้ ถ้าเปิด 2 session ในโฟลเดอร์เดียวพร้อมกันก่อนที่ hook จะส่ง event มา อาจสลับกันชั่วคราวจนกว่า hook ตัวแรกจะมาถึง
